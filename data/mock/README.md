# Mock data for the venue booking agent

Generated by `generator/generate_mock_data.py` (seed 2026, so it is reproducible). Everything here is fictional except the letterhead text and the venue names. People's names, emails and companies are made up.

To regenerate: `uv add reportlab`, then `uv run python data/mock/generator/generate_mock_data.py --out data/mock`.

## Planted patterns (test cases)

| Pattern | Where it appears | What the agent should do |
| --- | --- | --- |
| Admission counselling in **A Block SH for about two weeks every March** (2024, 2025, 2026) | Admissions Office circulars and reports | A March request for A Block SH gets a soft-conflict warning and an alternative |

## Built-in messiness

Dates appear as `08.03.2025` or `8 March 2025`; times as `09.30 AM` or `09:30`; venues by aliases such as `Seminar Hall, A Block`, `A-Block Seminar Hall`, `CC4 Lab`, `Centre of Excellence (COE2)`. About 20% of events have no report, which is realistic. Headcounts in reports differ from those in circulars.

## Mock faculty mails

`mails/mock_mails.json` holds 12 fictional threads: 9 that should turn into bookings (each with an `expected_booking` answer, including two that should trigger soft-conflict warnings: an A Block SH request in March and a COE lab request on a placement-training Saturday) and 3 unrelated mails as noise.

`mails/load_mock_mails.py` inserts them into your own Gmail under a `VBA-Mock` label using the Gmail API's insert call, so nothing is sent to anyone. See the top of the script for the one-time setup (add `http://localhost:8080/` as a redirect URI on the OAuth client). Delete the label's mails in Gmail to remove them.
